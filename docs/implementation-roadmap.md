### Memory boundary API (local owner)

- `GET/POST /api/research/memory/approvals`: POST `notebookId`, exact `revision`, `action` (`approve` or `revoke`), and a nonempty `reason`. Draft findings cannot be approved. Times and actor identity are server assigned.
- `GET/POST /api/research/memory/snapshots`: POST `mode` (`isolated` or `context-aware`), `knownAt` (UTC ISO instant), and explicit `approvalIds`. Isolated artifacts require an empty selection. Context-aware artifacts require 1–30 distinct currently active approvals that existed by the cutoff. Notebook and evidence creation times must also precede the cutoff.
- `GET /api/research/memory/snapshots/:id`: inspect the exact frozen context, hash and caveats. Historical reads remain available after revocation; new consumption must pass `usableMemorySnapshot` authorization checks.

This is an owner-controlled foundation, not organizational ACLs. Paired execution is described separately below. Explicit controlled Ask requests enforce their context boundary; ordinary Ask requests retain the existing broad research retrieval behavior. Approval permits reuse but does not certify the finding as true.

### Controlled copilot requests

`POST /api/ask` accepts an optional `memory` object: `{ "mode": "isolated" }` or `{ "mode": "context-aware", "snapshotId": "mem_…" }`. These opt-in analysis requests reject earlier chat history, attached chats, page context and prior backtest inputs instead of silently discarding them. Isolated requests create an empty immutable snapshot and cannot call `research_memory`. Context-aware requests validate current approval, preload the selected notebook revisions as untrusted tool evidence, and refuse requests for unselected notebooks or other saved-record kinds. Responses include the mode, snapshot ID, cutoff and hash on the final event. The normal tool-output size limits still apply; cited tool evidence records what was actually delivered to the model.

The answer-cache identity includes memory mode and snapshot. Controlled requests now bypass answer-cache reuse to preserve a fresh execution trace; ordinary requests retain caching. Approvals are checked before controlled execution and memory reads. Revoking an approval prevents new requests from reusing its context. Content already delivered to an in-flight model cannot be retroactively withdrawn. The cutoff constrains saved memory, not live external tools; this alone is not proof of a historically isolated trading evaluation. User-facing mode selection is implemented. Live-provider acceptance and team ACLs remain open. A mode applies to one fresh request; subsequent ordinary questions retain ordinary chat behavior.

### Pre-event market-model comparison

Event studies now optionally register `model: market-model`, `estimationSessions` (20–252) and `estimationGap` (0–60). The default remains `market-adjusted`, with expected return equal to SPY. For the market model, centered OLS with an intercept estimates security daily return = alpha + beta × SPY daily return separately for each event. Estimation ends before the first event-window return, separated by the registered gap; every estimation return and its preceding close must exist. Event-window and gap returns do not enter the fit. Missing estimation history, nonfinite calculations or benchmark daily-return variance at or below 1e-14 exclude the event explicitly.

Each result preserves alpha, beta, R-squared, residual standard deviation, estimation dates, the preceding-close date and all estimation samples. Daily abnormal returns subtract the chosen expected return. The report also shows simple SPY-adjusted CAR for the exact same included cohort, avoiding a coverage-driven comparison with a separately registered study. The buy-and-hold difference remains compounded security return minus compounded SPY return for either model. The UI labels this distinction and exposes model/estimation controls and per-event diagnostics. Old frozen reports remain readable and export their original engines; an unevaluated registration requires a new plan after an engine change.

This is a single-market-factor model of raw returns, not risk-free-adjusted CAPM or a multi-factor implementation. Fit diagnostics are descriptive; dependence-aware inference, multiple-testing controls and causal identification remain open. ### Event-study dependence diagnostics
